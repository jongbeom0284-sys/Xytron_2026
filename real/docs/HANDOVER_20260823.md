## 1. 시스템 구조 (누가 무엇을 하는가)

```
카메라 30Hz ─┬─ yolop_drive        차선(YOLOPv2 TensorRT) + 모든 주행 판단 + 모터 발행
             ├─ traffic_perception 신호등 (정규화 색도, 20Hz)
             └─ vehicle_perception 앞차 (YOLOv8n, 3프레임당 1회 = 10Hz)
라이다 10Hz ── cone_perception     라바콘 게이트·벽 계산 → /cone/reading
                                   (평소엔 자고 있다가 /cone/trigger 를 받아야 15초 깬다)
```

**주행 판단은 전부 `yolop_drive` 한 노드에 있다.** 나머지는 관측만 낸다.

라바콘 3단계 — 이 셋을 섞어 부르면 대화가 꼬인다:

| | 이름 | 어디 | 하는 일 |
|---|---|---|---|
| **A** | 주황 트리거 | `yolop_drive._check_cone_trigger` | 흰 차선 위 주황 ≥`cone_trigger_px`(300) 가 3장 연속 → `/cone/trigger` 1회 발행 |
| **B** | 콘 인식 ON | `Cone_Perception` | 트리거를 받으면 15초 창이 열리고 그동안만 `/scan` 계산 |
| **C** | 콘 모드 | `yolop_drive` 의 `ConeLink` | `/cone/reading` 을 받아 **조향을 라이다 벽 추종으로 인계** (`basis=cone`) |

## 2. 오늘 고친 것 (근본 원인 → 조치)

### 2-1. 【최우선】 구독 누수 — "점점 느려지던" 진짜 원인

`Vehicle_Perception.on_compressed()` 본문 **끝**에 `create_subscription('/kobot_yolop/status')`
가 들여쓰기 실수로 들어가 있었다 (커밋 `be8c5e2`, 0822 23:08). 카메라 프레임마다(30Hz)
구독이 하나씩 영구히 늘었다.

실측 (부팅 84분 뒤): 구독 **634개**(632개가 vehicle 하나), CPU **233%**,
`/vehicle/state` **30Hz → 0.485Hz**, status 메시지 유실, 서비스 누적 CPU 7h26m/1h46m.

→ `__init__` 으로 옮김. 회귀 방지 테스트 `test_node_structure.py` (AST 로 콜백 안
`create_*` 금지). 격리 도메인 검증: OLD 2→182개 / NEW 3개 고정.

> **이 누수가 그때까지의 모든 튜닝 값을 오염시켰다.** 특히 `CAR_CONFIRM=5` 는
> "2Hz 기준 2.5초"로 잡힌 값인데 지금은 30Hz 라 0.10초다. 예전 코드 주석의
> 시간 환산은 전부 믿지 말 것.

### 2-2. 직진 구간 (초록 확정 ~ 콘 트리거)

- **노란선을 목표에서 뺀다** — `LaneConfig.white_center_only`. 흰선 두 줄 중앙만 쓴다.
  이유: 삼거리에서 좌회전 도로의 노란 중앙선이 직진 도로 좌측 흰선과 **마스크상 붙어
  있다**. 노란선을 목표로 삼는 한 어떤 방식이든 좌측으로 끌린다.
- **오염 방지(`straight_only`)는 함께 켠다.** 이걸 빼면 흰선이 노랑 덩이에 먹혀
  `white_mask` 에서 빠지고, 흰선이 2줄로 안 잡혀 흰선 중앙 추종 자체가 성립하지 않는다.
  (f309 실측: 오염방지 켬 → 흰 덩이 2개·흰 화소 2665 / 끔 → 1개·1225)
- **조향 억제 기본 끔** (`straight_hold_sec` 0.0). 흰선 중앙이 이미 차로 중앙이라 불필요.
  되살리려면 초를 넣으면 되고, 창은 "신호가 시야에서 사라진 시점 + delay" 부터다.
- **속도 상한 1.6 m/s** (`straight_speed_mps`).

**끝나는 시점은 A(주황 트리거)다.** 그 순간 `_straight=False` 로 노란선 우선 추종
(=오염되는 상태)으로 돌아간다. **그게 정상이다** — 콘 구간 밖에서는 오염된 노란선을
따라가는 것이 이 팀의 설계다. 콘 탈출 때 따로 켤 필요 없다.

### 2-3. 콘 진입

- A 는 초록 확정 후 `cone_trigger_delay_sec`(2.0초) 뒤부터 센다 (신호등 앞 주황 오발동 방지).
- A 가 울리면 **라이다 콘 개수·게이트 유효를 보지 않고 즉시 C 진입** (`ConeLink.request_enter`).
  조건을 기다리다 0.7초를 흘린 실측이 있다 (192730/f262~268: 콘 1~3개·게이트 무효로 대기,
  5개가 되어서야 진입).
- **진입 시 속도 램프를 0 이 아니라 0.7 m/s 에서 시작** (`SpeedPolicy.prime`).
  `policy.reset()` 뒤 첫 `step()` 이 현재속도를 0 으로 강제하는 분기가 있어서,
  콘 진입마다 2.16 → **0.29 m/s** 로 곤두박질했다 (실측).

### 2-4. 라바콘 주황을 노란 씨앗에서 제외

콘은 주황이라 LAB b* 축에서도 양수 → 차선 마스크와 겹친 콘 화소가 **노란 중앙선 씨앗**이
되어 그 덩이에 붙은 흰선까지 물들였다.
실측(195303/f130): 콘 화소 14,797개 중 **50개**가 씨앗이 되어 흰선 덩이 **442화소**를
노랑으로 만들었다(`reclaim_white` 가 411개는 되찾았지만, 그건 `straight_only` 켜졌을 때만 돈다).

노랑 H≈25~35 / 콘 주황 H 3~12 로 **색상이 다르다** → `exclude_cone_orange` 로 갈라낸다.
실프레임 12장 검증: **직진 구간 씨앗 손실 0.0%**, 콘 구간에서만 0.3~12.7% 제거.

### 2-5. 앞차 인식

- `CONF_THRES` 0.12 → 0.50 → **0.30**, 클래스 **car 만** (bus/truck/suitcase 제외).
  기록주행 1218프레임 재분석: 전체클래스 0.12 → 검출 639개(대부분 suitcase 오검출),
  car만 0.50 → 41개(너무 적음), **car만 0.30 → 73개·회피 성립 11구간**.
- `CAR_CONFIRM` 5 → **3** (`car_confirm` 파라미터). 단위는 `/vehicle/state` **메시지 수**다.
  30Hz 발행에 추론은 10Hz(같은 판정이 3번씩 실려 나감) → 3 = 검출 1회, 5 = 2회, 9 = 3회.
- 추론 없는 프레임은 JPEG 디코드를 생략한다 (발행 30Hz 는 유지).

### 2-6. 신호등 노드 경량화

`find_lamps` 가 탐색 띠(화면의 2%)만 보면서 계산은 640×480 전체를 float 로 했다.
띠+여유만 크롭 → **19.6ms → 3.4ms**, 467프레임×2 ROI 에서 **결과 0 mismatch**.
`max_hz` 제한을 디코드 **앞**으로 옮겨 버릴 프레임을 풀지 않게 했다.

### 2-7. 대시보드 '전체 재시작' 이 스택을 못 살리던 버그

`clean_restart.sh` 는 첫 줄에서 `kobot-race.service` 를 멈추는데, **대시보드 자신이 그
서비스 cgroup 안에** 있다. systemd 는 `KillMode=control-group` 으로 cgroup 전체를 죽이므로
스크립트도 함께 죽었다 → 정지만 되고 재기동이 영영 안 왔다 (journal: 18:27:07 Stopped 뒤
Started 없음). `start_new_session=True` 는 세션·프로세스그룹만 바꿀 뿐 **cgroup 을 벗어나지
못한다.** → `systemd-run --user` 로 user.slice 에 맡겨 해결. API 호출로 end-to-end 검증함.

## 3. 주행 중 바꿀 수 있는 값 (재빌드·재시작 불필요)

```bash
# 앞차
ros2 param set /vehicle_perception_node conf 0.25          # 검출 임계
ros2 param set /vehicle_perception_node infer_interval 3   # N프레임당 1회
ros2 param set /yolop_drive car_confirm 5                  # 확정 메시지 수 (3=검출1회)

# 직진 구간
ros2 param set /yolop_drive straight_speed_mps 1.6         # 속도 상한 (0=제한없음)
ros2 param set /yolop_drive straight_hold_sec 0.0          # 조향 억제 (0=끔)
ros2 param set /yolop_drive straight_hold_delay_sec 1.0    # 억제 시작까지
ros2 param set /yolop_drive straight_hold_gain 0.15        # 억제 중 조향 배율

# 라바콘
ros2 param set /yolop_drive cone_trigger_delay_sec 2.0     # 초록 후 주황 감시까지
ros2 param set /yolop_drive cone_entry_speed_mps 0.7       # 진입 속도 시작점
ros2 param set /yolop_drive cone_trigger_px 300            # 주황 임계 (0=트리거 끔)

# 차선 조향 (LIVE_LIMITS 안의 값 전부)

ros2 param set /yolop_drive max_rate 400.0
```

**빌드가 필요한 값** (코드 상수): `cone_enter_frames`(런치 인자로는 됨),
`CONE_TRIG_CONFIRM`, `GO_CONFIRM`, `AVOID_HOLD_SEC`, `cone_gate_lost_exit_s` 등.

**잘 돌던 시점 스냅샷**: `real/config/baseline/yolop_drive_20260823_1p6_ok.yaml`
```bash
ros2 param load /yolop_drive real/config/baseline/yolop_drive_20260823_1p6_ok.yaml
```

## 4. 미해결 — 다음 사람이 이어받을 것

### 4-1. 콘 진입 첫 조향이 변화율 제한을 안 받는다 (분석 끝, 미적용)

`cone_wall.steer_for(aim, gain, prev_steer)` 에 틱당 6 제한이 있는데:
```python
if prev_steer is None:
    return want          # ← 제한 없이 통과
```
콘 모드 진입 시 `ConeLink._wall_prev = None` 이라 **첫 조향이 그대로 나간다.**

실측(195303/f129): 진입 첫 프레임 `aim=-0.221m` → **steer +32.8** 이 그대로 발행 →
0.5초 뒤 차가 우측 12cm 로 밀림(f133 콘 좌표: 좌+0.44/우-0.20) → 되돌리려 -35.4 좌측 풀락 → 진동.

그 `aim=-0.221` 자체는 **좌측 벽 콘이 1개뿐**이라 나온 값이다. 콘 1개로는 직선을 못
맞추므로 `centre_line` 이 **우벽 기울기(0.357, 콘 2개로 잰 값)를 좌벽에도 그대로** 쓰고
0.55m 앞을 외삽했다. 0.25초 뒤 콘이 10개 잡히자 `aim=+0.006` 으로 스스로 정상화된다.

**제안**: 진입할 때 `_wall_prev` 를 **직전 차선 조향값으로 seed**. 그러면 첫 틱 ±6 으로
제한되고, 그 사이(6틱≈0.3초)에 aim 이 정상으로 돌아와 급조향이 아예 안 나온다.

### 4-2. 콘 구간 중 red 오검출로 콘 인식이 꺼진다 (원인 확정, 미적용)

`Cone_Perception._on_signal()`:
```python
elif state in ('left', 'red'):
    self.open_until = 0.0      # ← 트리거로 연 15초 창을 즉시 지운다
```
`yolop_drive` 는 초록 확정 후 30초간 신호를 무시하지만(`_go_locked_until`),
`Cone_Perception` 은 **별도 노드라 그 잠금을 모른다.** `/traffic_light/state` 원본을
그대로 믿는다.

실측 (19:57:39): A 발화 → B 켜짐 → C 진입까지 0.04초 만에 성공했는데,
**0.77초 뒤 `직진 해제(red) — 콘 인식 끔`** 으로 B 가 꺼졌고 0.6초 뒤 C 도 이탈했다.
그 주행의 114행 중 **110행이 `X 진입 대기`**(B 꺼짐), `cone_active` 는 6행뿐.

**제안**: 트리거로 열린 창은 신호로 끄지 않는다 (창은 어차피 시간으로 닫힌다).
`_on_signal` 에서 `open_until` 을 지우는 부분만 빼면 된다.

### 4-3. 곡선 이탈 @ 2.16 m/s (분석 끝, 미적용)

곡선에서도 속도가 **27.0 units = 2.16 m/s 고정**이다 (중앙값=최대값). `yolop_drive` 에는
곡선 감속이 없다 — 신호등 정지와 콘 구간 말고는 속도가 상수다.

실측(182301, t=225): `e_far` 가 0.2초 만에 -0.067 → -0.731 로 뛰고 조향이 **-40 풀락**
으로도 못 따라가 이탈. 곡선 구간의 **14.3% 가 풀락**이었다. 1.6 m/s 에서는 잘 간다.
차선 상실률도 갈린다: 1.6 → 1%, 2.16 → 4~5%. **풀락이므로 게인을 올려도 안 된다.**

**제안**: 조향/오차 크기에 비례한 곡선 감속 (직선 2.16 유지, 곡선만 1.6).
2-2 의 `straight_speed_mps` 는 직진 구간 전용이라 곡선 문제는 아직 그대로다.

### 4-4. 배터리 (하드웨어, 본선 전 필수)

0822 실측: 부하 7A 에 전압 9.2 → **6.1V 폭락**(내부저항 ~400mΩ, 정상의 5~10배) →
7.5V 컷오프 → DRV 폴트 → 차가 기어감. **"모터가 느리다"의 최종 원인이고 VESC·코드
문제가 아니다.** 팩 교체 시험 필요. (Traxxas 7셀 NiMH, 8.4V 기준으로 계산할 것)

### 4-5. 로깅 구멍

`drive_logger` COLS 에 `cone_triggered`, `cone_trig_px` 가 없다. 그래서 주행 로그만으로는
**주황 트리거가 울렸는지 알 수 없다**(journal 로그로만 확인 가능). `raw_steer` 컬럼은
`LaneResult` 에 그 필드가 없어 **항상 0** 이다 — 조향 변화율 병목 분석에 못 쓴다.

- `~/drive_logs/drivelog_*.csv` — 주행 판단 전수 (status 5Hz)
- `~/motor_logs/motorlog_*.csv` — VESC 실측 (50Hz: erpm, 전압, 전류, 폴트)
- `~/cone_logs/conelog_*.jsonl` — 콘 좌표·조준값·**원본 스캔**
- `~/recordings/camera/<세션>/*.jpg` — 원본 프레임 10Hz (대시보드 기록 주행 시)
- 프레임 파일의 mtime 과 drivelog 의 `wall` 이 같은 epoch 축이라 **시각으로 동기화된다**

---

## 6. 이 차에서 사람을 여러 번 속인 함정

1. **`ros2 topic info` 는 daemon 캐시가 낡는다.** 구독자 수를 셀 때 `--no-daemon` 을 쓰거나
   rclpy 로 직접 세라. 634개짜리 누수가 daemon 으로는 **2개**로 보였다.
2. **`ros2 topic echo/pub --once` 는 디스커버리 전이면 유실된다.** 스크립트에서 쓰지 말고
   rclpy 로 붙어서 확인하라 (`race_go.sh` 가 재시도를 넣은 이유).
3. **`pkill -f <패턴>` 이 자기 ssh 세션까지 죽인다.** 명령줄에 패턴 문자열이 들어가기 때문.
   `~/cleanup.sh` 처럼 `printf` 로 패턴을 쪼개 만들어라.
4. **`colcon build` 를 빼먹으면 반영 안 된다** (build/ 는 복사본).
5. **LiDAR 노드를 두 개 띄우면** 같은 `/dev/ttyUSB0` 을 물어 `/scan` 이 2.3Hz 로 떨어진다.
   런치 전 `pgrep -c -f xycar_lidar_node` 가 1인지 확인.
6. **재생과 실주행은 다르다.** 재생은 저장된 사진을 새 추적기로 다시 계산하므로 시간 상태
   (조향 필터·hold)가 다르다. 마스크·램프·박스는 프레임만으로 정해지므로 같다.
   뷰어의 `LOG steer` 는 실주행 로그값이고, 그림은 재계산값이다.
7. **Windows 에서 파일을 만들어 scp 하면 CRLF** 가 되어 git diff 가 파일 전체로 뜬다.
   `newline='\n'` 으로 쓰거나 `sed -i 's/\r$//'`.
8. **부팅하면 `kobot-race.service` 가 자동으로 뜬다** (dashboard:=true 포함).
   본선 절차는 대시보드 없이 띄우는 것이므로 먼저 `sudo systemctl stop kobot-race.service`.

## 7. 본선 절차 (요약, 자세한 건 `real/docs/RACE_DAY_RUNBOOK.md`)

```bash
sudo systemctl stop kobot-race.service           # 부팅 자동 스택 내리기
source ~/kobot_env.sh
ros2 launch race_last race.launch.py             # 터미널 A: 인식 + 상황판
ros2 launch kobot_vehicle motor.launch.py armed:=true   # 터미널 B: 모터
~/race_go.sh 2.0                                 # 출발 (enabled + armed)
~/race_halt.sh                                   # 정지
```
전체를 한 번에: `bash ~/clean_restart.sh` (정지 → DDS 정리 → 재기동 → 모터).
정지가 90초 타임아웃까지 가므로 **약 1분 40초** 걸린다 (`yolop_drive` 가 SIGTERM 으로
안 내려가서 SIGKILL 까지 감 — 이것도 미해결이지만 주행엔 무관).
