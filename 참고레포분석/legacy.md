## B. 아키텍처 / 상태기계

**"미션별 컨트롤러 노드 + 중앙 멀티플렉서"** 구조. 5개 자체 노드 + 외부 2개(YOLO, 라이다 클러스터).

```
[usb_cam] ─┬→ lane_detection ──────→ /lane_control(xycar_motor) ─┐
           ├→ obstacle_position_check → /obstacle_position_check(Int16) ─┤
[yolov5_ROS] → /yolov5_pub ───────────────────────────────┤
[ar_track_alvar] → ar_follow ──→ /ar_control(xycar_motor) ─┼→ xycar_main2 (10Hz FSM/중재자) → /xycar_motor
[lidar_cluster] ─┬→ rubber_cone → /cone_control(xycar_motor) ┘
                 └→ (main이 직접 구독, 미션 트리거 판정용)
```

- 각 미션 노드는 **항상** 자기 제어값을 계산·발행하고, main(`xycar_main2.py`)이 미션 플래그에 따라 어느 토픽을 `/xycar_motor`로 릴레이할지 선택한다.
- 상태기계는 enum 없이 bool 플래그 조합(`ar_flag/traffic_flag/cone_start/cone_in_progress/cone_end/obstacle_start/obstacle_end`)으로 구현 (`xycar_main2.py:42-51`).
- 메인 루프 10Hz(`xycar_main2.py:71`). **6개 입력 토픽이 전부 살아있어야 어떤 동작(정지 발행 포함)도 수행** (`xycar_main2.py:74`) — 시작 전 준비상태 게이트로는 좋으나 주행 중 노드 사망 시 위험(§F 함정 참조).
- 플래그 체인으로 본 코스 순서: 신호등 → AR 구간(20초) → 차선 주행 → **라바콘 → 고정장애물** (초기값 `obstacle_end=True`이므로 라바콘이 먼저 트리거 가능, 라바콘 종료 시 장애물 트리거 개방 — `xycar_main2.py:50-51,118-128`. 교대로 반복 가능한 구조).

## C. 7회(2024) 미션별 구현 — 코드에서 역추정한 미션 구성

이 레포가 대상으로 한 미션: **①신호등 출발(적/녹 2색, YOLO) ②AR 마커 4개 통과 구간 ③차선 주행 ④라바콘 슬라럼 ⑤고정 장애물(차량 모형) 회피**. 2026 규칙에 있는 **랩카운팅·지름길·동적 방해차량 추월·통과감지장치는 코드에 없음** — 7회 미션엔 없었거나 수동 처리로 추정.

### C-1. 신호등 + 출발
- YOLO 클래스 기반: **class 0=적색등, class 1=녹색등** (`xycar_main2.py:298,336`). HoughCircles가 아니라 학습 모델.
- 대회 규정상 "자이카 실행 후 카메라를 가린 상태로 대기"하므로, **적색이 안 보이면 무조건 정지** (`xycar_main2.py:83-85` 주석 명시) — 가림 상태 오동작 방지.
- 적색이 멀리 보이면 AR 추종으로 신호등까지 전진 접근(`:91-92`), 적색 bbox 면적 ≥ **9000px²** 이면 근접 판정·정지 대기(`:315-326`), 녹색 검출 시 신호등 단계 종료(`:80-81`).
- 적색 소실 디바운스: 5프레임 연속 미검출 시 소실 처리(`:304-311`) — 단 여기 복붙 버그 있음(§F).

### C-2. AR 마커 구간 (7회 고유 미션)
`ar_follow.py` — ar_track_alvar 기반, 마커 4개를 순서대로 "스쳐 지나가는" 슬라럼형 주행.
- **통과 판정: 가장 가까운 마커의 ID가 바뀌면 직전 마커를 통과한 것** (`ar_follow.py:126-127,134-135` 등). 후보 등록 조건은 z<1.3m(첫 마커만 1.3<z<2.0m, `:154`).
- 구간별 접근 한계거리 `dis`: 시작 2.0 → 녹색 후 1.0 → 1번 통과 후 1.4 → 2번 후 0.95 → 3번 후 1.35 → 4번 후 1.0 (m) (`:30,108,129,137,145,153`).
- 원거리(z>dis): `angle=(x+add_x_pos)*add_angle` (녹색 후 add_x_pos=-0.1, add_angle=200; `:107-110,157-160`). 구간별 고정 조향 오버라이드: 2~3구간 z≥1.35→+20, 0.95≤z<1.35→+50; 3~4구간 z≥1.35→-20 (`:162-169`).
- 근거리(z≤dis): **조준점을 마커에서 ±0.5m 비켜서** `angle=(x+variable)*200`, variable=-0.50 (`:107,172-174`) → 마커를 옆으로 스침.
- **마커 소실 시 구간별 고정 조향으로 블라인드 주행**: 1→2구간 +15, 2→3구간 +20, 3→4구간 -20 (`:112-118`) — 코스 형상을 하드코딩한 폴백.
- main은 이 구간을 **녹색 후 고정 20초**만 돌리고 2초 정지 후 차선 주행으로 전환 (`xycar_main2.py:102-108`) — 마커 인식 실패에도 구간을 반드시 탈출하는 시간 기반 안전장치.

### C-3. 차선 주행
`lane_detection.py` — 원근변환 없는 ROI Hough 방식.
- 파이프라인: gray→GaussianBlur(5,5)→**Canny(60,75)**(`:87`)→ROI(행 300~380, `:20-21`)→**HoughLinesP(ρ=1,θ=1°,th=5,minLen=50,maxGap=10)**(`:99`)→기울기 |slope|>0.05 필터(`:118`)→좌(음기울기·x2<320-45)/우(양기울기·x1>320+45) 분리(`:134-140`)→평균 직선 적합→기준행 L_ROW=40에서 좌우 교점.
- **한쪽 차선만 보이면 차선폭 330px 가정으로 반대편 생성** (`:216-219`).
- 조향: `angle = atan(x_err/240)/(π/2)*150` (`:238-240`) — max_angle 150으로 스케일(하드웨어 ±50 포화 의존).
- 속도 고정 15 (`:16`).

### C-4. 라바콘 (라이다 클러스터 체이닝) ★이 레포의 백미
`rubber_cone.py` — 클러스터 중심점들을 좌/우 콘 라인으로 엮고 라인 길이 비대칭으로 곡률을 선반영.
1. 시드: y>0(좌) / y<0(우) 각각에서 최근접점, 단 **0.7m 이내**일 때만 채택 (`:90-103`).
2. 체이닝: 현재 점보다 x가 크고(전방) **0.4m 이내**인 점을 반복 연결해 라인 구성 (`:36-45`).
3. 웨이포인트: 좌/우 라인 길이차 `n=min(|diff|,4)` 만큼 **긴 쪽 라인의 n번째 점**과 짧은 쪽 0번째 점의 중점 (`:47-73`) — 콘이 많이 보이는 쪽(=커브 바깥/안쪽) 방향으로 조준점을 깊게 잡아 **곡률 선행 조향** 효과.
4. 조향: `angle = atan(-y_wp/x_wp)/(π/2)*200`, 속도 10 (`:125-133`).
5. **편측만 보이면 반대쪽으로 풀락(±200→하드웨어 포화 ±50)** (`:116-123`), 둘 다 없으면 정지(`:111-114`).
- 미션 진입 판정(main): 전방 0<x<1.0m, |y|<0.6m 박스 안 클러스터 점 **6개 이상** (`xycar_main2.py:237-248`). 종료: 카메라 라바콘 5프레임 연속 미검출 (`:398-405`).

### C-5. 고정 장애물(차량 모형) 회피
2단 인지 + 개루프 회피.
- **위치 판정 노드** `obstacle_position_check.py`: BEV(warp src=(100,320),(-150,400),(540,320),(790,400)→640x480, `:21-44`)에서 Canny(100,150)+HoughLinesP로 **중앙 차선(center line)** 추출(`:167-247`), YOLO class 4(차량) bbox 중심을 원근역변환한 중앙선 x와 비교해 **좌(0)/중(1)/우(2)** 발행 (`:88-104`, 판정 폭 Offset=40px `:30`).
- **트리거**(main): YOLO class4 면적≥4000px² 5프레임 연속(`xycar_main2.py:414-422`) AND 라이다 전방 0<x<1.5m·|y|<0.2m 최근접점<1.0m(`:250-266`).
- **회피 실행**: 위치별 3종 개루프 S자 (0.1s 간격 sleep 루프, `xycar_main2.py:131-187`):
  - 장애물 좌측(0)→우로 회피: 0.1s 직진(spd5) → **1.1s 조향+35/spd15 → 1.2s 조향-25/spd15**
  - 장애물 우측(2)→좌로 회피: 0.1s 직진 → **1.2s -35/15 → 1.2s +25/15**
  - 장애물 중앙(1)→좌로 크게: 0.1s 직진 → **1.5s -50/spd10 → 1.6s +35/spd10**
- 회피 1회 후 플래그 리셋, 다음 라바콘 트리거 개방 (`:189-191`).

## F. 노하우 / 함정 (주석·코드 근거)

**노하우**
1. **카메라 가림 출발 대기**: "대회 규정을 보면 자이카를 실행시켜놓고 카메라를 가린 상태로 대기" (`xycar_main2.py:83` 주석) → 적색 미검출=정지라는 방어 로직. 2026에도 동일 운영이면 필수.
2. **이중 센서 미션 트리거**: 카메라(YOLO 면적+연속 프레임) AND 라이다(전방 박스 점수/거리) 동시 만족 시에만 미션 진입 (`:118,128`) — 오탐으로 인한 조기 미션 진입 방지.
3. **N연속 검출/미검출 디바운스**(진입 5프레임, 이탈 5프레임 @10Hz)를 모든 미션 전환에 일관 적용.
4. **시간 상한 탈출**: AR 구간을 인식 성공 여부와 무관하게 20초로 강제 종료 — 인지 실패로 미션에 갇히는 것 방지.
5. **마커 통과 판정 = 최근접 ID 변화**: 거리 임계 하나로 판정하는 것보다 강건.
6. **편측 인지 폴백**: 콘 한쪽만 보이면 풀락, 차선 한쪽만 보이면 고정폭(330px) 가정 — 인지 부분 실패 시에도 제어 연속성 유지.
7. 회피 방향을 "장애물이 중앙선 기준 어느 쪽인가"로 선택하는 **BEV 중앙선 대비 판정** — 2026 추월 미션의 "주행하지 않는 차선으로만 추월" 방향 결정과 동형.

**함정 (실코드 버그 — 그대로 베끼면 안 됨)**
1. `xycar_main2.py:118` — `self.first_check_rubber_cone_detected` **괄호 누락**으로 메서드 객체(항상 truthy)를 조건으로 사용. 결과적으로 라바콘 진입이 라이다 단독 조건이 됨. 우연히 동작했지만 의도와 다름.

## G. 2026 우리 스택(kmu_race) 이식 / 반면교사

**이식 가치 높음**
1. **라바콘 체이닝+인덱스 중점 알고리즘** → `perception/cone_detector.py`(현 HSV 콘) + `perception/lidar_tracker.py` 클러스터 출력에 그대로 얹을 수 있음. HSV 색 기반보다 라이다 기반이 조명 불변이고, "긴 라인 쪽 n번째 점" 트릭은 퓨어퍼수트 lookahead 포인트 생성기로 변환 용이. 수치(링크 0.4m, 시드 0.7m, n≤4)는 콘 간격이 비슷하면 초기값으로 유효.
2. **회피 S자 타이밍/기하**: 자이카 실차에서 검증된 "0.1s 직진 → ~1.1-1.2s 바깥조향(±35) → ~1.2s 복귀조향(∓25), 중앙 장애물은 -50/+35에 1.5/1.6s" — 우리 정적장애물 회피와 **추월 후 90cm 복귀** 기동의 시간·각도 초기값으로 사용. 단 sleeps 대신 `race_fsm.py`의 시간 파라미터화 상태로 구현할 것.
3. **좌/중/우 장애물 위치 판정**(BEV 중앙선 vs 장애물 중심, ±40px) → 추월 방향 결정 로직(`core/policy.py`)에 이식. 우리는 BEV 차선 + 라이다 클러스터가 이미 있으므로 접합 비용 낮음.
4. **디바운스·이중센서 트리거·시간상한 탈출** 패턴 → `race_fsm.py` 전이 가드 표준으로 채택.
5. **가림 카메라 출발 대기** → `signal_detector.py`/FSM 초기 상태에 "신호등 미검출=정지 유지" 반영.
6. AR 관련 로직은 2026 미션에 AR가 없으면 폐기. 다만 "최근접 대상 ID 변화 = 통과" 아이디어는 겐트리/통과감지장치 목격 랩카운팅(`core/target_passing.py`)의 중복 카운트 방지에 응용 가능.

**반면교사**
- blocking sleep 금지(회피 중 실명), 데드맨 워치독 필수(입력 스테일 시 정지 발행 — `core/safety.py`에 이미 있다면 유지), 조향 포화를 암묵 의존하지 말고 명시 클램프, 미호출 함수·복붙 카운터 같은 버그는 유닛테스트(우리 test/ 디렉토리)로 차단.

## C. 미션별 구현 (템플릿 미션 셋 + 자체 차선)

이 레포가 대상으로 한 미션 구성: 템플릿 기준 **출발선 AR 접근 → 신호등(3구) → AR 추종 → 라이다 벽(미로)주행 → 차선 주행 → AR 주차**. 8회 실전 미션(라바콘/장애물/추월/랩카운팅)의 자체 구현은 **없다**. 즉 이 레포의 가치는 미션 로직이 아니라 ① 자이트론 템플릿 원형 보존 ② 자체 BEV 차선 파이프라인 구조에 있다.

### C-1. 신호등 (자이트론 템플릿 원형, 3구 — 2026은 4구이므로 확장 필요)

- ROI: 중심 (320,100)에서 ±(220,80) → 상단 440x160 영역 (`:285-286`).
- gray→blur→**HoughCircles(dp=1, minDist=20, param1=40, param2=20, R=15~25px)** (`:281,299-301`).

- **기하 정합성 검사** (★핵심 노하우):
  - 수직 산포: 최상단·최하단 원 y차 ≤ 2×MAX_RADIUS(=50px) (`:361-364`)
  - 수평 폭: 좌우 끝 원 x차 ≤ 8×MAX_RADIUS(=200px) (`:367-370`)

2. **미션별 카메라 노출 프로파일**을 v4l2로 런타임 전환 — 신호등(저노출)과 차선(중노출)의 요구가 다름을 하드웨어 레벨에서 해결.
3. `kill_node()`로 불용 인식 노드 제거해 연산 확보(`track_drive_01.py:235-244`, 호출부는 주석) — Jetson/TX2급 보드에서 유효한 기법.
4. 초음파 8채널 이동평균/중앙값 필터 클래스(min/max/가중 이동평균 선택지 포함, `:61-110`).
5. `saveToImage.py`/`camera.py`: 주행 영상→프레임 추출, 체커보드(10x7) 캘리브레이션 등 **오프라인 튜닝 워크플로** 흔적 — BEV 좌표를 실차 영상으로 잡는 절차.

**함정 (치명)**
1. `LaneDetect.py:8` — 생성자가 `def init(self)` (`__init__` 아님) → `LaneDetector().forward()`는 `self.canny` 부재로 **AttributeError**. 게다가 `lane_detect()`가 매 프레임 객체를 새로 생성 (`track_drive_01.py:493-495`).
2. `LaneDetect.py:3`/`LaneLines.py:225` — `from Hough import *`인데 파일명은 `hough.py` → **리눅스(케이스 민감)에서 ImportError**. 커밋 상태로는 실행 자체가 안 됨 = 실차 검증 안 된 스냅샷이라는 강한 증거.
3. `hough.py:10-14` — `HoughLinesP` 결과 None 가드 없음(빈 화면에서 크래시).
4. `LaneDetect.py:18` — `_, pos, detected = LaneLines.forward()`인데 실제 반환은 `(img, found, pos)` → 변수명이 뒤바뀜(값 흐름은 우연히 정상, 가독성 함정).
5. PID 게인 차원 불일치(§D) — 구조만 참고하고 값은 버릴 것.

## G. 2026 우리 스택(kmu_race) 이식 / 반면교사

**이식 가치 높음**
1. **신호등 기하 정합성 검사 3종**(수직 산포·수평 폭·등간격)을 우리 `perception/signal_detector.py`(HoughCircles 4구)에 추가 — "정확히 4원 + 일직선 + 등간격 + 4번째 원 최대 밝기(또는 파란 위치 원 밝기 급증)"로 바꾸면 됨. 오탐 억제에 즉효.
2. **미션별 노출 프로파일**: 출발 대기(신호등) 저노출 ↔ 주행(차선) 중노출 전환을 `io` 계층 또는 launch에서 v4l2-ctl로. 값 0/20/100은 자이카 카메라 기준 출발점.
3. **정지선/횡단 흰띠 검출기**(V≥180, 밀도 52%)를 겐트리 목격 랩카운팅(`core/target_passing.py`)의 보조 신호로 — 통과감지장치 부근 노면 특징과 조합하면 카운트 이중화 가능.
4. 속도적응 조향 감쇠 + 코너 부스트 **구조**(`ControlCar.py`)는 우리 `core/speed_policy.py`/PID에 이미 유사 개념이 있다면 교차 검증용.
5. 슬라이딩윈도우 세부(히스토그램 중앙 ±50 제외, minpix 게이트, 편측 고정폭 폴백)는 우리 BEV 차선 검출기와 동일 계열 — 파라미터 비교 대상.

**반면교사**
- import/생성자 오타로 전체 파이프라인이 죽는 사례 → 우리 스택의 test/ 스모크 테스트(모듈 임포트+1프레임 forward)가 왜 필수인지 보여줌.
- 템플릿 FSM을 통째로 주석 처리하고 무한루프 하나만 남기는 방식은 되돌리기 어렵다 — 우리처럼 FSM 상태를 켜고 끄는 구성이 옳음.

## H. 신뢰도: **하** (자체 코드) / **중** (자이트론 템플릿 유래 부분)

- 하 근거: 단일 커밋 준비 단계 스냅샷, 커밋 상태로 실행 불가(임포트·생성자 버그), PID 미튜닝, 실주행·결과 기록 전무.
- 중 근거: 신호등/정지선/노출/AR 수치는 자이트론 공식 템플릿 값으로 다수 팀이 실차에서 사용해온 계열(tj2024의 차선 코드도 같은 템플릿 계보 — Canny 60/75, ROI 300~380 등이 일치).
